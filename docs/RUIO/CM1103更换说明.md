# ADS1115 更换为 CM1103 说明

本文面向需要把 Vibratalkie 喉振 ADC 采样率从当前约 800 Hz 提高到最高 2 kHz 的用户。

## 1. 结论

- CM1103 和 ADS1115 都是 16 位、4 通道、I2C 接口的 ΔΣ ADC。
- ADS1115 最高为 860 SPS，CM1103 最高为 2000 SPS。
- 更换 CM1103 可以提高时间分辨率，但不会提高位数；2 kSPS 下噪声还会高于低速模式。
- 只更换芯片、不修改程序时，设备仍按默认 800 Hz 读取和上传，无法得到 2 kHz 数据。
- PC Raw Stream 的 VTK1 UDP 包格式不需要修改，包头已经包含实际采样率。
- 2 kHz 的奈奎斯特频率为 1 kHz。如果需要保留 1 kHz 以上的喉振细节，应改用至少
  8～16 kSPS 的 ADC 或音频 Codec 输入，CM1103 仍然不够快。

参考数据手册：

- [CM1103 数据手册](https://datasheet.lcsc.com/datasheet/pdf/fcde1d7db915dd2473ee5153bb391023.pdf?productCode=C20606814)
- [ADS1115 数据手册](https://www.ti.com/lit/ds/symlink/ads1115.pdf)

## 2. 硬件更换

### 2.1 引脚检查

CM1103 的 MSOP10 与 ADS1115 的 VSSOP10 功能引脚排列一致：

| 引脚 | 功能 | Vibratalkie 连接 |
|---:|---|---|
| 1 | ADDR | GND，I2C 地址为 `0x48` |
| 2 | ALERT/RDY | 当前程序未使用 |
| 3 | GND | 地 |
| 4 | AIN0 | 喉振传感器模拟输出 |
| 5 | AIN1 | 未使用或按原电路连接 |
| 6 | AIN2 | 未使用或按原电路连接 |
| 7 | AIN3 | 未使用或按原电路连接 |
| 8 | VDD | 3.3 V |
| 9 | SDA | I2C SDA |
| 10 | SCL | I2C SCL |

必须先确认实板安装的是 10 引脚 VSSOP/MSOP 封装，并核对焊盘尺寸与 1 脚方向。
CM1103 的 QFN10 型号不能直接焊到 VSSOP/MSOP 焊盘上。

### 2.2 更换步骤

1. 断开 USB、锂电池和所有外部电源。
2. 记录原 ADS1115 的 1 脚方向，使用热风拆下芯片并清理焊盘。
3. 焊接 MSOP10 封装的 CM1103，确保 1 脚方向正确、相邻引脚无连锡。
4. 确认 VDD 与 GND 之间没有短路；保留芯片附近原有的 `0.1 µF` 去耦电容。
5. 上电前确认 AIN0 电压不会低于 GND−0.3 V 或高于 VDD+0.3 V。
6. 上电后先扫描 I2C，确认 `0x48` 可以正常应答。

不要让 ADS1115 和 CM1103 同时连接在地址 `0x48` 上。±4.096 V 是 ADC 的数字满量程，
不是允许输入超过 3.3 V 电源的意思；模拟输入仍必须满足芯片绝对最大额定值。

CM1103 和 ADS1115 的模拟输入阻抗指标并不完全相同。若喉振传感器输出阻抗较高，换芯后
可能出现幅度衰减、频响变化或噪声增加。建议先确认传感器前级是否有运放缓冲；没有缓冲时，
应实测换芯前后的静态电压、信号幅度和频响，必要时增加高输入阻抗缓冲器。

## 3. 当前程序为什么必须修改

板级代码当前写入配置寄存器：

```cpp
uint8_t config[] = {0x01, 0xC2, 0xE3};
```

`0xC2E3` 的公共部分含义为：

- AIN0 对 GND 单端采样；
- PGA 满量程 ±4.096 V；
- 连续转换；
- 禁用比较器。

但 `DR=111` 在两个芯片上的含义不同：

| 芯片 | `DR=111` 对应速率 |
|---|---:|
| ADS1115 | 860 SPS |
| CM1103 | 2000 SPS |

因此换成 CM1103 后，这个配置字可以继续使用，ADC 内部会以 2 kSPS 转换。但是当前
`CONFIG_PC_RAW_STREAM_ADC_RATE` 默认为 800，最大值也被限制为 860；采样任务仍每
1250 µs 只读一次转换寄存器，所以会跳过大量 CM1103 转换结果。

## 4. 必需的软件修改

### 4.1 放宽 PC Raw Stream 的采样率范围

修改 `main/Kconfig.projbuild`：

```kconfig
config PC_RAW_STREAM_ADC_RATE
    int "CM1103 sample rate (samples/second)"
    default 2000
    range 1 2000
    depends on PC_RAW_STREAM_MODE
```

如果同一份代码还需要兼容 ADS1115，建议不要直接固定为 2000，而是增加 ADC 型号选择：

```kconfig
choice VIBRATALKIE_ADC_TYPE
    prompt "Throat vibration ADC"
    default VIBRATALKIE_ADC_ADS1115

    config VIBRATALKIE_ADC_ADS1115
        bool "ADS1115 (max 860 SPS)"

    config VIBRATALKIE_ADC_CM1103
        bool "CM1103 (max 2000 SPS)"
endchoice
```

然后根据型号设置合适的默认采样率，并避免 ADS1115 固件错误上报 2 kHz。

### 4.2 修改板级默认配置

修改 `main/boards/vibratalkie/config.json`：

```json
"CONFIG_PC_RAW_STREAM_ADC_RATE=2000"
```

也可以不修改板级默认值，烧录前在 `idf.py menuconfig` 中手动设置为 2000。

### 4.3 更新芯片名称和日志

`main/boards/vibratalkie/vibratalkie_board.cc` 中建议同步修改：

- `InitializeAds1115()` 改名为 `InitializeCm1103()`；
- `Ads1115PrintTask` 改名为 `Cm1103PrintTask`；
- `kAds1115Address` 改名为 `kCm1103Address`；
- 初始化成功和失败日志中的 `ADS1115` 改为 `CM1103`；
- 注释中的 `860 SPS` 改为 `2000 SPS`。

配置字仍使用：

```cpp
// CM1103: AIN0-GND, ±4.096 V, continuous mode, 2000 SPS, comparator off.
uint8_t config[] = {0x01, 0xC2, 0xE3};
```

如果希望先用噪声稍低的 1000 SPS，CM1103 的 `DR=110`，配置应为：

```cpp
// CM1103: AIN0-GND, ±4.096 V, continuous mode, 1000 SPS, comparator off.
uint8_t config[] = {0x01, 0xC2, 0xC3};
```

此时 `CONFIG_PC_RAW_STREAM_ADC_RATE` 也应设置为 1000。

### 4.4 PC 上位机是否需要修改

现有 PC 工具解析 VTK1 包头中的 `sample_rate`，正常情况下不需要修改协议或 CSV 格式：

- `pc_raw_stream_server.py` 可以接收 2 kHz ADC 记录；
- `adc_raw.csv` 字段不变；
- `metadata.json` 会记录设备上报的 ADC 采样率；
- `pc_stream_dataset.py` 优先使用元数据中的采样率。

仍应把文档里固定写成 800 Hz、860 SPS、奈奎斯特频率 400 Hz 的内容更新为实际配置。
第三方上位机如果把 800 Hz 写死，也必须改为读取 VTK1 包头的 `sample_rate`。

## 5. 2 kHz 运行时的可靠性

当前采样链路使用 500 µs 周期的软件定时器唤醒 ADC 任务，再通过 400 kHz I2C 读取一次
转换寄存器。理论上可以运行到 2 kHz，但还会受到 I2C 总线占用、WiFi 调度和任务延迟影响。

当前任务通知使用合并方式：如果 ADC 任务来不及处理，多个定时通知可能合并，实际采样率
会下降。若实测无法稳定接近 2 kHz，可以按以下顺序优化：

1. 确保同一 I2C 总线上没有高频轮询其他器件。
2. 提高 ADC 任务优先级，并统计连续两次样本时间戳差值。
3. 将 CM1103 `ALERT/RDY` 配置为转换完成信号，用 GPIO 中断唤醒 ADC 任务。
4. 必要时为 ADC 使用独立 I2C 控制器。
5. 在 AIN0 前增加适合 2 kHz 采样的模拟低通滤波，截止频率应低于 1 kHz。

如果当前 PCB 没有把 `ALERT/RDY` 引到 ESP32-S3 GPIO，第 3 项需要飞线或改版，不能只靠
软件开启。

UDP 侧不需要提高包数。现有程序按 `ADC_RATE / 50` 个样本组包：2 kHz 时每包 40 条
记录，仍约为每秒 50 个 ADC UDP 包。

## 6. 编译和验证

```bash
idf.py menuconfig
# Xiaozhi Assistant → VIBRATALKIE_CONFIG
# ADC rate 选择 2000

idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

开始 PC 采集后检查：

1. `metadata.json` 中 ADC 采样率为 2000。
2. `adc_raw.csv` 相邻 `device_timestamp_us` 通常约差 500 µs。
3. 采集报告中的 `adc_effective_rate_hz` 应接近 2000，而不是 800。
4. 串口中没有持续出现 I2C 读取失败或 UDP 发送失败。
5. 用已知频率的安全小信号测试 100、400、800 Hz，检查 FFT 峰值位置是否正确。

如果相邻时间戳大量超过 500 µs，说明软件调度或 I2C 读取没有跟上。此时不能仅在协议中
把采样率写成 2000；应先解决漏采，或者退回稳定的 1000 SPS。

## 7. 推荐方案

- 首次换芯先使用 **1000 SPS**，确认硬件、底噪和 I2C 稳定。
- 稳定后再切换到 **2000 SPS**，实测有效采样率和丢样情况。
- 若目标只是提高到约 1 kHz，CM1103 是较低改动的替代方案。
- 若目标是获得接近音频波形的数千赫兹带宽，不建议继续使用这类低速 ADC。
